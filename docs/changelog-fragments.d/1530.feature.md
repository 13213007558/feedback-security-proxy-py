Added an explicit final route admission phase to the HTTP proxy so
authorization is always evaluated against the host:port the proxy actually
connects to, for both plain proxy requests and `CONNECT` tunnels.

- New `HttpProxyBasePlugin.authorize_route` hook runs after all request
  rewriting but before any upstream socket is opened. A single plugin
  rejecting the route denies it and no connection to the denied destination
  is established.
- Destination changes made after admission are re-authorized; changing the
  destination of an already pinned upstream connection raises
  `RouteAuthorizationRejected` (HTTP `403`) instead of bypassing policy.
- `FilterByUpstreamHostPlugin` and `FilterByURLRegexPlugin` now enforce their
  policy from `authorize_route` while keeping their legacy hooks for
  backward compatibility.
